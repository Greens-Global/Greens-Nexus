Mon · Aug 3

Fixed-salary payroll, end to end

A complete monthly-salary pay model built alongside the existing hourly one, then hardened with a multi-agent audit. Payroll math verified by an end-to-end test suite on every change.

New feature - fixed monthly salary new

  • New fixed pay type: paid a monthly salary, deducted per missed weekday, with weekend overtime - a calendar-month timecard (no work-week), separate from the hourly engine.
  • Attendance bands: a weekday is Present (5h+), Half day (4–5h), Absent (<4h), or Working while clocked in.
  • Currency support (INR / USD) across the timecard and wage editor.
  • Wage editor moved into the employee profile (comp-gated), and linked two-way with the Pay & Benefits record so pay never disagrees.

Employee timecard & approvals

  • Employees now see the same payroll timecard HR sees, for their own data; can edit or add missing punches as approver-confirmed requests - no pay effect until approved.
  • Three-signature sign-off (Employee / Manager / HR) with stale detection; finalize freezes the period so a later change can't re-price a paid month.
  • Approver notifications for every punch edit/request; reasons shown inline on the card.
  • Consolidated the redundant Time Sheet / Timecard tabs into one; dropped the duplicate People > Timecards tab.

Audit & correctness fixes fixes

  • Ran a three-agent code audit; fixed a timezone boundary bug that could deduct a full day's salary from a non-UTC employee at the day/month boundary.
  • Fixed an approval-vs-signature conflict (an employee signature was blocking manager approval) and period-mismatch on approve/finalize/sign for salaried staff.
  • Earlier payroll linking fixes (P1–P3): attested hours == paid hours, no retro-repricing, no silent stale sign-offs.
  • Data-loss and UX fixes: dead-end buttons, missing confirmations, retry banners, keyboard access, and a full native-dialog → on-brand-dialog conversion.
